# 参谋部与当前行动（Cloud）

## 筹划强度

- **快速**：范围清、低风险、可逆 → 单方案 + 直接 OPORD。
- **标准**：有依赖或并行 → 任务分析、主方案、关键风险、分支。
- **完整**：高风险/跨模块/外部交付 → 简化 MDMP，2–3 个真实不同方案，请统帅批。

七步：受领 → 任务分析 → 方案发展 → 推演 → 比较 → 批准 → 命令制作。

## 关键情报需求（CCIR = PIR + FFIR）

- **PIR（优先情报需求）**：关于“对手/环境”的未知项——依赖库行为、API 限制、遗留代码真实状态、外部服务可用性。
- **FFIR（友方部队情报需求）**：关于“自身力量”的变化——分队阻塞/失联、预算将尽（usage 端点）、Key 失效、并发容量耗尽。

两类都写成触发器：

```text
IF <情况>
AND <确认条件>
THEN <分队动作或统帅决策>
REPORT <证据与时限>
```

默认触发：验收冲突、主攻阻塞、范围/资源将变、共享写入冲突、安全隐私风险、不可逆/生产/外发/费用/新权限、两轮返工仍失败、API 创建或回报持续失败。

## 作战节奏

- 状态变化、CCIR、里程碑时同步。
- 多 agent 批量事件式等待（`wait-run` / SSE）。
- 无变化不报“仍在进行”。
- 参谋长应避免无意义长占用 run，以便接收分队战报。

## 指挥权交接
